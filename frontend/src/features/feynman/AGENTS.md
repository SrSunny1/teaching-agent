## 一、这个模块要做什么

用**费曼技巧**逼学生把知识讲清楚：学生用自己的话复述一个概念 →
Agent 扮演「只会追问的初学者」，找出表述中的**模糊点**与**逻辑跳跃**，逐层追问（**至少 3 轮**）→
最后给出**对照评价与改进建议**。

**它解决什么教学问题**：学生以为自己懂了，其实只记住了名词。追问能逼出漏洞。
这是「抽象知识形象化」之外的另一条认知路径 —— **从「看懂」到「讲得出」**。

**界面上长什么样**：右栏画布显示**追问时间线**，每轮一段：
「Agent 的追问 → 学生的回答 → 点评」，最后一轮后显示总分与总评。

## 二、数据形状

后端工具返回 `ToolResult(..., artifact_type="feynman", artifact={...})`，
前端从 `props.artifact?.data` 读它：

```json
{
  "concept": "回火",
  "rounds": [
    {
      "question": "你说回火是「再加热一次」，那为什么不直接淬火到想要的硬度就停手？",
      "userAnswer": "因为淬火冷得太快，工件内部会有很大的应力……",
      "critique": "方向对了。但你只说了「开裂」，没说清应力是从哪来的……",
      "annotated": [
        { "text": "因为淬火冷得太快，", "kind": null },
        { "text": "工件内部会有很大的应力", "kind": "good", "note": "抓到了应力来源，这是对的。" },
        { "text": "……", "kind": null }
      ]
    }
  ],
  "score": 78,
  "overall": "……",
  "suggestions": ["……"]
}
```

### `annotated` —— 逐句标注（本模块的交付重点）

`annotated` 是把该轮 `userAnswer` 切成**互不重叠的完整分段**，供画布把学生原话逐句高亮。

- **硬性不变式**：各段 `text` 顺次拼接必须与 `userAnswer` **逐字相同**。前端是拿它直接渲染的，
  拼不回去就等于把学生的话改了。
- `kind` 是封闭集合：`vague`（表述模糊）/ `jump`（逻辑跳跃）/ `good`（讲对了）；`null` = 未标注的普通文字。
- 只有带 `kind` 的段才带 `note`（针对这一句的点评）。
- **切分由后端 `_annotate()` 算好，前端只渲染** —— 前端不做任何定位或切分计算。

**模型给的是引文，不是下标。** 工具 schema 里每轮有个可选的 `marks: [{quote, kind, note}]`，
模型只负责指出「是哪句话」（`quote` 必须是原文里原样出现的片段）。定位在后端用子串匹配做，
**对不上原文的引文直接丢弃**（宁可少标，不可标错位置）。`annotated` 是后端产物，
模型不直接产出这个字段。

**封闭集合**：`relation` = 前置依赖/因果/对比/组成；`type` = 成分/相/组织/性能/工艺/缺陷。
**JSON 字段一律 camelCase。**

## 三、当前状态

- ✅ **前端 `Component.tsx` 已实现**：追问时间线（追问 / 回答 / 点评）+ 总评，
  以及**逐句标注**（点击标注看该句点评）
- ✅ **后端 `feynman_followup` 已建**：规范化时间线、三轮门槛、`_annotate()` 逐句标注切分
- ★ **三轮门槛按「已回答的轮次」算，不是按 `rounds` 长度**（`answered = sum(1 for r in rounds if r["userAnswer"])`）。
  前端进度条同理显示「已回答 N 轮 / 至少 3 轮」。**改这两处任一处都要同时改另一处**，
  否则会出现「第 4 轮 / 至少 3 轮」这种自相矛盾的进度。
- ★ **Agent 在「刚抛出问题、学生还没回答」时也会调一次工具**（`userAnswer` 传空、不传 `critique`），
  这样画布从出题那一刻起就有内容，而不是整个问答过程一片空白。
  `critique` 因此**不在 schema 的 required 里** —— 强制必填会诱导模型跳过这种轮次。
  ⚠️ 这条触发时机是**靠 `description` 里一个具体例子约束住的**，实测：
  只写规则（「包括你刚抛出问题的那一轮」）模型不会照做，写上
  「学生说『开始追问我吧』→ 你回『请讲讲…』→ 这一轮就要调用」它才稳定执行。
  **改 description 时别把那个例子删掉。**
- ✅ 追问策略已写进工具 `description`：**「先找模糊点 → 再找逻辑跳跃 → 最后给对照评价」**
- ✅ **逐句标注已用真实对话验证**（2026-10-14，deepseek-chat）：模型确实会产 `marks`，
  后端切分后 6 段、3 处标注、拼接与原话逐字一致。
  ⚠️ **但这是靠提示词约束出来的，有随机性**：第一版 description 里留了一句
  「整段都没问题时省略这个字段」，模型就顺势整个跳过了 `marks`（实测两轮标注全空）；
  改成「userAnswer 非空则 marks 必填、至少 1 处」之后才稳定产出。
  **改这段 description 时别把这条约束放松**，否则标注会静默消失 —— 而且不报错，
  只是退化成一段普通文字，很难发现。
- ✅ **2026-10-17 换模型后重新验证**（deepseek-chat 已下线，现在是 `deepseek-flash`）：
  在**明确的一问一答**下，3 处标注全部正确产出并渲染，说明标注能力没受换模型影响。
- ⬜ **已知空白：学生最初那段讲解不会进画布。**
  典型开场是「我来讲讲什么是回火：淬火后硬度高，但组织比较脆……」—— 这段话**不是对某个追问的回答**，
  而 `rounds` 的形状是 `{question, userAnswer}` 成对出现，模型塞不进去，只能记一条空回答的轮次。
  实测：这种开场下 `userAnswer` 为空、`marks` 为空，**学生最丰富的那段原创表述反而没被标注**。
  要补的话有两条路：
  1. **提示词层**：让模型把学生初始讲解填进第 1 轮的 `userAnswer`（语义顺序略拧：问题是在讲解之后才问的）；
  2. **数据形状层**：顶层加一个 `initialAnswer`，在时间线上方单独渲染并标注（语义干净，但要同时改前后端和契约表）。
  **还没做决定，先记在这里。**

## 四、验收标准

**通用三条（必须过）：**

- 左栏点进来 → `preview.ts` 的样例数据能正常渲染
- 对话里提问 → 触发工具 → 画布显示真实结果（右上角「预览数据」标签消失）
- `python scripts/check-boundaries.py` 全绿

**本模块特有：**

- 左栏点「费曼追问」→ 能看到**三轮追问的时间线**渲染（每轮：追问 / 回答 / 点评）
- **逐句标注**：学生的回答上能看到黄（表述模糊）/ 红（逻辑跳跃）/ 绿（讲对了）三种高亮，
  **点击**某段弹出针对这一句的点评；顶部有图例说明三种颜色
- 标注必须**只落在学生真的写过的那句话上** —— 模型给的引文对不上原文时应被丢弃，
  **宁可不标，不可标错位置**（`_annotate` 的行为，有一次性测试覆盖）
- 模型没产 `marks` 时，界面退回渲染纯文本回答，**不报错、不白屏**
- 对话里说「我来讲讲什么是回火」→ Agent 开始追问，画布实时更新轮次
- **至少 3 轮追问后才允许给出总评**（不到 3 轮就给分是不合格的）
- 学生答非所问时：**先澄清问题再回主线**，不要无限追问
- 总评要能指出「哪一句表述模糊」「哪一步逻辑跳了」，不能只给个分数

## 五、怎么写（四条约定）

1. **从 `props.artifact?.data` 读数据。** `null` 就是还没数据，显示空态。
2. **本地交互即时反馈** —— 切换轮次这类**不要发网络请求**。
3. **需要 Agent 干活时调 `props.onSendMessage('...')`。**
4. **要把新状态推回画布时调 `props.onEmitArtifact('feynman', {...})`。**

**两条硬约束：**

- **不要在组件里自己发网络请求。** 需要数据就让 Agent 去调工具。
- **不要改 `tokens.css`。** 样式用它已有的类，要自定义就写内联样式。

**追问逻辑放 Python 后端 / 模型侧，前端只负责把 `rounds` 画成时间线** ——
不要在前端实现评判逻辑。
